# 보스 콘셉트 시트

> **목적:** `Exception`의 보스들이 어떤 프로그래밍 언어/개발 도구에서 출발했는지, 그리고 이를 액션 보스전으로 어떻게 바꿀지 정리한다.

## 1. 전체 콘셉트

플레이어는 오류가 폭주한 런타임 내부로 진입하고, 각 보스는 특정 언어/도구의 상징이 변형된 예외 개체로 등장한다.

- 보스는 단순 패러디가 아니라, 각 언어/도구의 이미지와 개발자 밈을 전투 패턴으로 번역한다.
- 메인 진행에서는 **보스 3전 (Serpent.py → Vritra → CMD)** 를 완성한다.
- 포트폴리오에서는 "콘셉트가 시스템으로 연결된다"는 점을 보여주는 것이 핵심이다.

| 순서 | 보스명 | 모티브 | 실루엣 | 역할 |

| 최종 | **CMD** | CMD / Terminal | 인간형 (불완전 렌더링) | 클라이맥스 |

## 3. 1보스 — Serpent.py (Python)

### 핵심 이미지

- 파이썬의 파랑과 노랑을 각각 독립된 **사족보행 드래곤**으로 재해석
- **Vethara**는 사파이어 계열 색감의 비늘과 날개를 지닌 물/얼음 드래곤
- **Aurathos**는 토파즈 계열 색감의 비늘과 날개를 지닌 번개 드래곤
- 보석은 색상과 스킬의 모티브일 뿐이며, 몸 전체를 결정이나 보석 갑옷처럼 표현하지 않는다.
- 체형은 거대한 도마뱀보다 강아지·고양이처럼 민첩하고 감정이 읽히는 사족보행 실루엣
- 서로 다른 몸체와 HP를 가지며, 한 마리가 위험해지면 다른 한 마리가 적극적으로 엄호

### 역할

처음 만나는 Primordial Exception. 전투 루프(패링 → 그로기 → 처형)를 학습시키는 튜토리얼 역할.

### 패턴 방향

| 페이즈 | 패턴 | 키워드 |
|---|---|---|
| Phase 1 | Tail Sweep Combo | 근거리 콤보. 패링 유도. |
| Phase 1 | Glacial Pounce | Vethara의 빙결 도약. 예고 데칼 학습. |
| Phase 1 | Thunder Pounce | Aurathos의 낙뢰 도약. 타이밍 회피 학습. |
| Phase 2 | Sapphire Rush | Vethara의 고속 돌진. 측면 회피 학습. |
| Phase 2 | Topaz Chain | Aurathos의 연쇄 번개. 두 보스와의 거리 조절 학습. |
| Phase 2 | Frost Script Field | 서리 장판. 공간 읽기 학습. |
| Climax | Twin Resonance | 두 보스가 모두 HP 20% 이하일 때 발동하는 얼음+번개 합동 필살기. |

### 처치 후 로그

> *"왜 너는 우리를 지우려 하는가. 우리가 없었다면 너도 없었다."*

## 4. 2보스 — Vritra (Perl)

### 핵심 이미지

- Perl 낙타 마스코트에서 출발한 사막 유목형 예외 개체
- 정규식, 해시, 원라이너 같은 Perl의 이미지를 전투 패턴으로 번역
- 중거리에서는 긴 라인 견제, 가까이 붙으면 몸통 충격파와 모래 장판으로 압박
- Serpent.py보다 넓은 사거리 판단과 돌진 회피를 요구한다.

### 비주얼

- 거대한 낙타형 실루엣. 높은 혹과 긴 다리로 위압감 형성
- 몸 표면에 `$`, `%`, `@`, `=~` 같은 Perl 기호가 룬처럼 흐름
- 공격 전 바닥에 정규식 라인, 해시 격자, 모래 장판 예고가 먼저 나타남
- 색상은 사막 앰버 + 보라빛 스크립트 발광 + 경고 레드 포인트

### 역할

2번째 보스. Serpent.py에서 배운 회피/그로기 루프를 **중거리 견제와 돌진 압박** 속에서 실전 적용하는 단계.

긴 전방 라인, 직선 돌진, 넓은 장판 예고를 읽고 안전한 측면/후방을 찾는 플레이를 가르친다.

### 패턴 방향

| 페이즈 | 패턴명 | 타입 | 키워드 |
|---|---|---|---|
| Phase 1 | Sigil_HumpCrash | AOE | 근접 몸통 충격파. 붙어서 때리는 플레이 견제. |
| Phase 1 | Regex_SpitLine | Melee Line | 정규식처럼 길게 뻗는 전방 라인 공격. |
| Phase 1 | Caravan_Rush | Dash | 낙타 돌진. 측면 회피와 후방 반격 학습. |
| Phase 1 | Hash_Sandstorm | AOE | 해시 격자형 모래 장판. 안전 지대 판단. |
| Phase 2 | Backtracking_Stomp | AOE | 넓은 연속 압박. 늦은 회피를 처벌. |
| Phase 2 | OneLiner_Pierce | Dash | 긴 한 줄 코드처럼 빠르게 관통하는 돌진. |

### 처치 후 로그

> *"한 줄이면 충분했다. 봉인을 깨운 명령도, 세계를 무너뜨릴 명령도."*

## 5. 최종보스 — CMD

### 핵심 이미지

인간형 실루엣. 그러나 **완전히 렌더링되지 않은** 느낌 — 와이어프레임이 깜빡이고, 윤곽이 흔들리며, 일부 부위가 픽셀화된다. The Runtime의 가장 깊은 명령줄 계층이 보스화된 존재.

### 비주얼

- **얼굴:** 반쯤 가려진 후드. 눈 위치에 터미널 커서(`█`)가 깜빡인다
- **몸:** 검은 로브 위로 흰 명령어 텍스트가 실시간으로 흘러내림
- **무기:** 없음. 허공에 명령어를 타이핑하면 그것이 공격으로 실행됨
  - `>SLASH`, `>EXECUTE`, `>FORK` 등 공격마다 텍스트가 먼저 표시됨
- **피격 시:** 몸 일부가 글리치되거나 픽셀화. 화면에도 글리치 이펙트

### 역할

최종 클라이맥스. 봉인된 보스들을 깨워 The Runtime을 파괴하려는 원흉이며, Hendel과 Nel이 마지막으로 막아야 할 존재.

CMD를 처치하면 The Runtime이 어떻게 될지 — 플레이어가 판단한다.

### 패턴 방향

| 페이즈 | 패턴명 | 타입 | 키워드 |
|---|---|---|---|
| Phase 1 | `>SLASH` | Normal | 명령어 소환 근거리 타격. 패링 가능. |
| Phase 1 | `>EXECUTE` | Smash/AOE | 좌표 지정 수직 폭발. 예고 타이핑 있음. |
| Phase 1 | `>MOVE` | Smash | 텔레포트 후 즉시 근접 타격. |
| Phase 2 | `>FORK` | 특수 | CMD 분열. 두 개의 분열체 동시 처치 필요. |
| Phase 2 | `>KILL -9` | 특수 | Hendel 조작 일시 차단 (1~2초). |
| Phase 2 | `>REWRITE` | 환경 변조 | 전투 공간 일부 지형/판정 변경. |

### 보스명 정리

| 항목 | 내용 |
|---|---|
| 보스명 | **CMD** |
| 부제 | *The First Command* |
| 모티브 | CMD / Terminal |
| 본질 | The Runtime의 의식. 모든 명령의 근원. |
| 처형 후 마지막 로그 | `> PROCESS: CMD — TERMINATED` |

## 8. 비주얼 가이드

- 과하게 귀엽게 만들기보다, 원본 아이콘의 특징을 "보스 실루엣"으로만 남긴다.
- 색은 언어/도구의 대표색을 참고하되, 전투 가독성을 우선한다.
- 텔 동작은 동물적(또는 기계적) 움직임으로 읽히게 만들고, 실제 판정은 명확한 기하 형태로 관리한다.
- CMD는 **인간형이지만 인간이 아님**을 비주얼에서 명확히 전달해야 한다.

## 9. 구현 메모

- 보스 콘셉트는 BP/애니메이션 레이어에서 바뀌어도 C++ 코어는 재사용 가능해야 한다.
- `BossSkillData`에 `SkillTag`, `AttackType`, `DamageProfileId`, `MontageKey`를 넣어 보스별 패턴 교체가 가능하게 설계한다.
- MVP 이후 다른 언어 보스를 추가할 때는 같은 `AExBossCharacter`와 `UExBossSkillComponent` 구조를 유지한다.
- CMD의 `>KILL -9` 패턴처럼 플레이어 입력을 차단하는 효과는 `DisableInput` + 타이머로 구현.
