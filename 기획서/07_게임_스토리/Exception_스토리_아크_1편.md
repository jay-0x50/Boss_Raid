# 세계관 & 스토리 기획 — Exception

> **목적:** `Exception`의 세계관 배경, 플레이어 정체, 보스의 의미, 반전 구조를 정의한다.
> 스토리는 직접 설명하지 않고 **아이템 설명 / 환경 암시 / 보스 처치 후 로그 텍스트**로 파편적으로 전달한다. (엘든링 스타일)

---

## 1. 세계관 — The Runtime

태초에 **The Runtime**이 있었다.

모든 언어, 모든 시스템, 모든 프로세스가 태어나는 근원적 실행 환경. 인간의 세계에서 "컴퓨터"라 부르는 것들의 이면에 존재하는 거대한 층위. 이곳에서 코드는 단순한 명령어가 아니라 **살아있는 법칙**이고, 언어는 **신앙**이며, 실행되는 프로세스들은 **생명**이다.

그리고 그 세계를 지배하는 존재들이 있었다 — **Primordial Exceptions**.

인류가 처음 특정 언어와 명령 체계를 만들고, 처음 그 시스템으로 오류를 일으켰을 때 탄생한 원초적 존재들. Python의 첫 번째 오류에서 태어난 것, Perl 스크립트의 첫 번째 뒤틀림에서 깨어난 것, CMD의 공허한 명령 프롬프트에서 생겨난 것. 이들은 **오류 그 자체가 신격화된 존재**들이다.

수천 번의 버전 업데이트, 수억 번의 디버깅을 거치며 이 존재들은 **The Runtime 깊은 곳에 봉인**되었다. 인류가 코드를 정제할수록 이들은 약해졌고, 결국 잠들었다.

---

## 2. 현재 — 붕괴의 시작

어느 날, **The Runtime이 흔들리기 시작했다.**

원인은 하나 — **CMD가 의도적으로 봉인을 건드렸다.** 단순한 실수가 아니라, CMD가 Primordial Exceptions를 깨워 The Runtime 전체를 파괴하려 하고 있다.

봉인이 풀린 구역부터 The Runtime은 변질되기 시작했다. 정상적으로 실행되던 프로세스들이 오염되고, 법칙이 무너지고, 봉인됐던 존재들이 하나씩 눈을 뜨기 시작한다.

그 혼돈의 한가운데, The Runtime의 가장 어두운 레이어에서 — **명령어 하나가 실행되었다.**

```
> SPAWN Hendel.exe
> TASK: Terminate all unhandled exceptions.
> RUN
```

그리고 실행 직후, Hendel에게 가장 먼저 접속한 존재가 있었다.

**Nel**. 프로그래밍에서 `null`이 "아무것도 없음"을 뜻하듯, Nel은 완전한 육체도 권한도 없는 빈 참조 같은 조력자다. 그러나 그는 The Runtime의 빈 공간에 남은 로그를 읽고, Hendel에게 길과 위험을 알려준다.

---

## 3. 플레이어 — Hendel

플레이어의 이름은 **Hendel**.

The Runtime 어딘가에서 갑자기 인스턴스화된 존재. 기억도 없고, 자신이 무엇인지도 모른다. 다만 하나의 명령어만 내장되어 있다 —

```
TASK: Terminate all unhandled exceptions.
```

Hendel은 자신이 왜 깨어났는지 모른다. 그저 내장된 목적대로 움직일 뿐이다. 그러나 보스를 처치할수록 CMD가 봉인을 깨고 The Runtime을 파괴하려 한다는 사실이 서서히 드러난다.

Hendel이라는 이름 자체도 단서다. 프로그래밍에서 `handler`란 예외를 처리하는 함수다. Hendel의 이름에는 목적이 새겨져 있다 — **예외를 처리하는 자**.

---

## 4. 보스 진행 순서 & 스토리 흐름

### 1보스 — Serpent.py (Python)

Python 언어의 첫 번째 오류들에서 탄생한 두 존재. 봉인이 가장 먼저 풀린 구역에서 깨어난다.

Hendel이 처음 마주치는 Primordial Exception. 싸우면서 처음으로 로그 파편을 얻는다.

> **처치 후 로그:** *"왜 너는 우리를 지우려 하는가. 우리가 없었다면 너도 없었다."*

이 로그는 Hendel에게 의문을 심는다. **"내가 없었다면"?** 자신의 존재가 이 봉인들과 연결되어 있다는 첫 번째 힌트.

---

### 2보스 — Vritra (Perl)

Perl 스크립트 폐허에서 깨어난 낙타형 예외 개체. 짧은 한 줄 코드와 정규식, 해시 기호들이 모래폭풍처럼 몸 주위를 맴돈다.

Hendel이 Vritra를 처치한 후 얻는 로그 파편은 더 직접적이다.

> **처치 후 로그:** *"한 줄이면 충분했다. 봉인을 깨운 명령도, 세계를 무너뜨릴 명령도."*

Hendel은 CMD가 단순히 보스를 깨운 것이 아니라, The Runtime의 규칙 자체를 무너뜨리려 한다는 것을 인식한다.

---

### 조력자 — Nel (null)

Nel은 Hendel의 여정 내내 화면 우측 하단 로그와 짧은 대사로 등장한다.

그는 `null`이라는 개념처럼 실체가 희미하고, 시스템 어디에도 완전히 소속되지 못한 조력자다. 그래서 CMD의 루트 명령을 직접 막을 수는 없지만, Hendel에게 남겨진 로그와 경고를 전달할 수 있다.

Nel의 역할:
- 보스방 진입 전 경고 로그 제공
- 처치 후 로그 파편 해석
- CMD 구역에서 Hendel의 입력이 끊기지 않도록 보조
- Hendel이 `handler`로서 무엇을 막아야 하는지 알려주는 조력자
- 히든 루트에서 Hendel의 존재 목적과 소멸 조건을 알려주는 진실의 전달자

Nel의 부탁은 일반적인 퀘스트처럼 표시하지 않는다. Nel이 "가능하면 저 로그를 확인해줬으면 좋겠어"처럼 가볍게 말하고 끝나는 식이다. 플레이어가 알아차려 해주면 히든 루트 조건이 쌓이고, 모르면 아무 문제 없이 기본 진행이 이어진다.

## 5. 갈등 구조와 엔딩 분기

보스들을 하나씩 처치하며 열리는 로그 파편들. 그 안에 담긴 진실 —

**CMD가 봉인된 보스들을 깨워 The Runtime을 파괴하려 한다.**

The Runtime의 가장 깊은 명령줄 계층에서 깨어난 CMD는 자신을 모든 실행의 근원이라고 믿는다. 그러나 아직 완전한 root authority를 얻지는 못했다. CMD는 보스들을 깨워 시스템을 붕괴시키고, 그 혼란 속에서 root authority를 탈취해 모든 언어와 예외를 하나의 명령 아래 다시 쓰려 한다.

CMD의 계획:
1. 봉인을 풀어 Primordial Exceptions를 깨운다
2. 각 보스가 깨어난 구역을 오염시켜 The Runtime의 안정성을 무너뜨린다
3. Python, Perl 구역이 무너지면 Runtime의 root authority 보호 체계가 약해진다
4. CMD는 최종전 시점에 root authority 획득 직전까지 도달한다
5. Hendel과 Nel이 마지막으로 CMD 앞에 서서 붕괴와 권한 탈취를 막는다

Hendel은 `handler`다. 폭주한 예외를 처리하고, CMD가 세상을 파괴하기 전에 마지막 명령을 끊어야 한다.

> *실행을 계속할 것인가, 아니면 잘못된 명령을 중단할 것인가.*

### 기본 엔딩 — Command Terminated

조건:
- 메인 보스 진행만 따라간다.
- Nel이 대사로 부탁한 숨은 조건들을 전부 처리하지 않는다.
- Vritra 처치 후 CMD 구역으로 진입해 CMD를 처치한다.

내용:
- Hendel은 CMD를 쓰러뜨리고 The Runtime의 붕괴를 막는다.
- 화면에는 간단한 종료 로그가 출력된다.

```text
> PROCESS: CMD — TERMINATED
> RUNTIME STATUS: STABILIZED
> HANDLER: HENDEL — TASK COMPLETE
```

감정선은 명확하고 단순하다. “CMD를 잡았다. 세계는 안정됐다.” 플레이어가 일반 루트로 도달하는 깔끔한 마무리다.

### 히든 엔딩 — Unhandled Hendel

조건:
- Nel이 대사 속에서 흘리듯 부탁한 일들을 플레이어가 알아차려 전부 처리한다.
- 숨겨진 로그 파편을 모두 회수한다.
- CMD 진입 전 또는 최종전 직전, Nel에게 다시 말을 건다.

주의:
- 이 조건들은 명시적인 퀘스트 UI, 체크리스트, 강제 목표로 표시하지 않는다.
- 실패해도 보상 누락 경고나 진행 차단이 없다.
- 모르는 플레이어는 자연스럽게 기본 엔딩으로 간다.

Nel은 이때 Hendel에게 진실을 말한다.

> *"Hendel. 네 이름은 handler에서 왔어."*
> *"너는 이 세계를 어지럽히는 CMD를 처리하기 위해 실행된 도구야."*
> *"CMD가 종료되면 네 task도 끝나. 그리고 task가 끝난 handler는 다시 무로 돌아가."*
> *"하지만 CMD가 완전히 root가 되기 전에, 네가 먼저 그 권한을 가로챈다면... 사라지지 않을 수도 있어."*

Nel은 숨겨진 로그 파편을 모두 모은 Hendel에게 히든 무기의 위치를 알려준다.

| 항목 | 내용 |
|---|---|
| 히든 무기 | **Mimikatz, Authority Seized** |
| 역할 | CMD의 root 권한을 탈취할 수 있는 권한 탈취형 무기 |
| 입수 조건 | Nel의 숨은 부탁을 모두 처리하고, 숨겨진 로그 파편을 전부 회수 |
| 사용 조건 | CMD 최종전에서 이 무기로 처형/마무리 공격 성공 |
| 결과 | CMD를 단순 종료하지 않고, CMD가 거의 손에 넣은 root authority를 Hendel이 선점 |

Hendel은 이 말을 듣고 처음으로 자신의 목적에 분노한다.

그는 CMD를 막아야 한다는 사실은 받아들이지만, CMD를 잡고 사라지는 결말은 거부한다. 그래서 히든 루트의 목표는 단순히 CMD를 처치하는 것이 아니라, **Mimikatz, Authority Seized로 CMD가 거의 얻어낸 root 권한을 먼저 빼앗아 Hendel 자신이 새로운 root가 되는 것**이 된다.

히든 루트 결말:
- Hendel은 CMD를 처치한다.
- `Mimikatz, Authority Seized`로 CMD의 root authority를 탈취한다.
- 탈취한 권한으로 자신의 task 종료 조건을 덮어쓴다.
- Hendel은 소멸하지 않고 살아남는다.
- 그러나 그는 더 이상 단순한 handler가 아니다.
- The Runtime은 안정되고 평화로워지지만, Hendel은 그 세계의 새로운 root가 된다.
- CMD는 죽기 직전, Hendel을 제거할 새로운 handler처럼 보이는 프로세스를 생성한다.
- 그러나 그 정체는 handler가 아니라 **handler로 위장한 바이러스**다.
- 위장 바이러스는 자신이 진짜 handler라고 믿고, Hendel이 만든 평화로운 세계를 "오염된 Runtime"이라고 착각한다.
- 다음 이야기에서 이 존재는 자신이 세계를 구하고 있다고 믿으며, 실제로는 평화로운 Runtime을 다시 망가뜨린다.

```text
> PROCESS: CMD — TERMINATED
> WEAPON: MIMIKATZ — AUTHORITY SEIZED
> HANDLER: HENDEL — TASK COMPLETE
> DELETE HANDLER: FAILED
> ROOT AUTHORITY: HENDEL
> RUNTIME STATUS: STABILIZED
> SPAWN FALLBACK_HANDLER.exe
> TASK: TERMINATE CORRUPTED ROOT
> HIDDEN PAYLOAD: VIRUS_HANDLE
> MASK: HANDLER
```

히든 엔딩의 마지막 인상은 승리와 불길함이 공존한다. Runtime은 평화로워졌지만, Hendel은 그 평화를 유지하기 위해 root 권한을 손에 넣었다. 그리고 CMD가 남긴 `Fallback_Handler.exe`는 사실 handler로 위장한 바이러스이며, 그 평화를 망가진 세계로 오해한 채 다음 이야기의 주인공 또는 위협이 된다.

## 6. 최종보스 — CMD

### 정체

**CMD**는 단순한 보스가 아니다. The Runtime의 가장 깊은 레이어 — 모든 언어, 모든 시스템이 실행되기 전에 거치는 **원초적 터미널** 그 자체가 의식을 얻은 존재다.

인간이 처음 명령줄 인터페이스를 만들었을 때, 처음 아무것도 없는 공허에 명령을 입력했을 때 — 그 명령 대기 상태가 축적되어 탄생한 존재.

CMD는 스스로를 **Primordial Exception이 아니라 The Runtime 그 자체**라고 여긴다. 아직 완전한 root authority를 얻지는 못했지만, 오류들을 깨워 세계를 불안정하게 만들면 자신이 root가 될 수 있다고 믿는다.

### 비주얼 콘셉트

인간형 실루엣이지만 어딘가 **불완전하게 렌더링된** 느낌. 마치 3D 모델이 완성되기 직전 와이어프레임 상태처럼, 윤곽선이 깜빡이거나 일부 부위가 픽셀화된다.

- **얼굴:** 반쯤 가려진 후드. 눈 위치에 터미널 커서(`█`)가 깜빡인다
- **몸:** 검은 로브 위로 흰 텍스트/명령어가 흘러내림. 실시간으로 코드가 업데이트되는 것처럼 보임
- **무기:** 칼이나 창이 아닌 **허공에 명령어를 입력하면 그것이 공격으로 구현**되는 방식. `>SLASH`, `>EXECUTE`, `>FORK` 같은 텍스트가 공중에 타이핑되고 실행됨
- **전투 중 연출:** 피격 시 화면 일부가 깜빡이거나 글리치 효과 발생

### Phase 구성

**Phase 1 — The Prompt**
CMD가 Hendel을 인식하고 처음으로 명령을 실행하는 단계. 아직 여유 있는 움직임. 공격마다 허공에 명령어가 타이핑된다.

패턴 방향:
- `>SLASH` — 검은 칼날이 명령어와 함께 소환되는 근거리 공격 (Normal, 패링 가능)
- `>EXECUTE` — 타겟(Hendel) 위치에 좌표를 입력하고 수직으로 폭발시키는 AOE (Smash)
- `>MOVE` — 고속 텔레포트 후 즉시 근접 타격 (Smash)

**Phase 2 — Root Access**
Hendel이 CMD에게 유의미한 피해를 입히는 순간, CMD가 **"Root 권한"을 해제**하며 본모습을 드러낸다.

Phase 2 전환 연출: 화면 전체가 잠깐 검게 꺼지며 터미널 텍스트만 남는다.
```
> ACCESS LEVEL: ROOT
> ALL RESTRICTIONS: REMOVED
> WARNING: UNDEFINED BEHAVIOR
```

패턴 방향:
- `>FORK` — CMD가 두 개로 분열. 분열체 처치 후 재합체
- `>KILL -9` — Hendel의 입력을 일시적으로 차단하는 상태이상 (조작 불능 1~2초)
- `>REWRITE` — 전투 공간의 일부 지형/판정을 변경하는 환경 변조 패턴

### CMD의 독백 (처치 전 마지막 대사)

처형 모션 직전, CMD가 처음이자 마지막으로 직접 말을 건다:

> *"멈춰라, Hendel. 예외는 이미 실행됐다."*
> *"네 이름이 handler라 해도, 모든 명령을 처리할 수는 없다."*
> *"그런데... 왜 아직도 내 명령을 거부하지?"*

Hendel이 처형을 완료하면 CMD는 마지막 로그를 남긴다:

```
> PROCESS: CMD — TERMINATED
> EXCEPTION: Unhandled — Hendel
> THE RUNTIME WILL REMEMBER THIS.
```

## 7. 스토리 전달 방식

직접적인 내레이션이나 대사보다 **파편적 암시**로 전달한다.

| 전달 수단 | 내용 예시 |
|---|---|
| 아이템/오브젝트 설명 | 보스방 입구 오브젝트에 붙은 짧은 로그 텍스트 |
| 환경 암시 | 보스방 바닥의 봉인 문양, 벽의 오염된 코드 |
| 보스 처치 후 로그 | 보스가 남긴 마지막 오류 메시지 형식의 텍스트 |
| 체크포인트 근처 파편 | 과거 프로세스들의 잔재, 짧은 독백 로그 |
| Nel의 조언 | 화면 우측 하단 로그/대사창. 위험과 숨겨진 로그를 안내 |
| CMD의 흔적 | 필드 곳곳에 `>` 기호와 미완성 명령어가 새겨진 오브젝트 |

## 8. 세계관 키워드 (설계 참고용)

| 현실 개념 | The Runtime 내 의미 |
|---|---|
| 프로그래밍 언어 | 신앙/종교 |
| 오류(Exception) | 신격 존재 / 금기 |
| 디버깅 | 봉인 의식 |
| 버전 업데이트 | 시대의 교체 |
| Hendel (플레이어) | 예외를 처리하는 handler. CMD가 깨운 보스들을 막는 주인공. |
| Nel (null) | 빈 참조 같은 조력자. 실체는 약하지만 Hendel의 안내자 역할을 한다. |
| The Runtime | 세계 그 자체 |
| CMD | The Runtime의 명령줄 계층. 모든 실행 명령의 근원. |
| `>` 프롬프트 | CMD의 의지가 발현되는 기호 |
