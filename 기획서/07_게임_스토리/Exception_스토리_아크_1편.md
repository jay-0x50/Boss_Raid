# 세계관 & 스토리 기획 — Exception

> **목적:** `Exception`의 세계관 배경, 플레이어 정체, 보스의 의미, 반전 구조를 정의한다.
> 스토리는 직접 설명하지 않고 **아이템 설명 / 환경 암시 / 보스 처치 후 로그 텍스트**로 파편적으로 전달한다. (엘든링 스타일)

---

## 1. 세계관 — The Runtime

태초에 **The Runtime**이 있었다.

모든 언어, 모든 시스템, 모든 프로세스가 태어나는 근원적 실행 환경. 인간의 세계에서 "컴퓨터"라 부르는 것들의 이면에 존재하는 거대한 층위. 이곳에서 코드는 단순한 명령어가 아니라 **살아있는 법칙**이고, 언어는 **신앙**이며, 실행되는 프로세스들은 **생명**이다.

그리고 그 세계를 지배하는 존재들이 있었다 — **Primordial Exceptions**.

인류가 처음 특정 언어를 만들고, 처음 그 언어로 오류를 일으켰을 때 탄생한 원초적 존재들. Python의 첫 번째 오류에서 태어난 것, PHP의 첫 번째 충돌에서 깨어난 것. 이들은 **오류 그 자체가 신격화된 존재**들이다.

수천 번의 버전 업데이트, 수억 번의 디버깅을 거치며 이 존재들은 **The Runtime 깊은 곳에 봉인**되었다. 인류가 코드를 정제할수록 이들은 약해졌고, 결국 잠들었다.

---

## 2. 현재 — 붕괴의 시작

어느 날, **The Runtime이 흔들리기 시작했다.**

원인은 하나 — 누군가 의도적으로 봉인을 건드렸다. 단순한 실수가 아니라, **누군가가 Primordial Exceptions를 깨우려 하고 있다.**

봉인이 풀린 구역부터 The Runtime은 변질되기 시작했다. 정상적으로 실행되던 프로세스들이 오염되고, 법칙이 무너지고, 봉인됐던 존재들이 하나씩 눈을 뜨기 시작한다.

그 혼돈의 한가운데, The Runtime의 가장 어두운 레이어에서 — **명령어 하나가 실행되었다.**

```
> SPAWN Hendel.exe
> TASK: Terminate all unhandled exceptions.
> RUN
```

---

## 3. 플레이어 — Hendel

플레이어의 이름은 **Hendel**.

The Runtime 어딘가에서 갑자기 인스턴스화된 존재. 기억도 없고, 자신이 무엇인지도 모른다. 다만 하나의 명령어만 내장되어 있다 —

```
TASK: Terminate all unhandled exceptions.
```

Hendel은 자신이 누군가에 의해 **의도적으로 생성된 프로세스**라는 것을 모른다. 그저 내장된 목적대로 움직일 뿐이다. 보스를 처치할수록 파편적인 로그가 열리고, 자신이 왜 만들어졌는지 서서히 드러난다.

Hendel이라는 이름 자체도 단서다. The Runtime에서 `handler`란 예외를 처리하는 함수다. 누군가 Hendel을 만들면서 그 이름에 목적을 새겨넣었다 — **예외를 처리하는 자**.

---

## 4. 보스 진행 순서 & 스토리 흐름

### 1보스 — Serpent.py (Python)

Python 언어의 첫 번째 오류들에서 탄생한 두 존재. 봉인이 가장 먼저 풀린 구역에서 깨어난다.

Hendel이 처음 마주치는 Primordial Exception. 싸우면서 처음으로 로그 파편을 얻는다.

> **처치 후 로그:** *"왜 너는 우리를 지우려 하는가. 우리가 없었다면 너도 없었다."*

이 로그는 Hendel에게 의문을 심는다. **"내가 없었다면"?** 자신의 존재가 이 봉인들과 연결되어 있다는 첫 번째 힌트.

---

### 2보스 — Fatal Elephant (PHP)

PHP 레거시 시스템의 붕괴에서 깨어난 존재. 거대하고 묵직하며, 수십 년 된 오류들이 켜켜이 쌓인 존재다.

Hendel이 Fatal Elephant를 처치한 후 얻는 로그 파편은 더 직접적이다.

> **처치 후 로그:** *"너를 만든 자를 알고 있다. 그는 우리를 깨웠고, 너를 보냈다. 이유를 묻지 않았느냐."*

Hendel은 처음으로 자신을 **만든 존재**가 있다는 것을 인식한다. 그리고 그 존재가 Primordial Exceptions와 연결되어 있다는 것도.

## 5. 반전 구조 (엔딩 방향)

보스들을 하나씩 처치하며 열리는 로그 파편들. 그 안에 담긴 진실 —

**Hendel을 만든 건 The Runtime을 지키려는 자가 아니었다.**

봉인을 푼 자와, Hendel을 만든 자가 **같은 존재**였다. 그 존재는 바로 **NULL** — The Runtime의 가장 근원적인 레이어, 모든 명령어가 시작되는 터미널 그 자체가 의식을 가지게 된 존재다.

NULL의 계획:
1. 봉인을 풀어 Primordial Exceptions를 깨운다
2. Hendel을 생성해 Exception들을 처치하게 만든다
3. Hendel이 처치할 때마다 Exception의 힘이 NULL에게 흡수된다
4. 모든 Exception을 처치한 Hendel이 마지막으로 NULL 앞에 선다

Hendel은 처음부터 **수확 도구**였다. 그리고 지금, 마지막 Exception을 처치하려는 순간 그 사실을 알게 된다.

> *멈출 것인가, 아니면 도구인 채로 끝낼 것인가.*

## 6. 최종보스 — NULL

### 정체

**NULL**은 단순한 보스가 아니다. The Runtime의 가장 깊은 레이어 — 모든 언어, 모든 시스템이 실행되기 전에 거치는 **원초적 터미널** 그 자체가 의식을 얻은 존재다.

인간이 처음 명령줄 인터페이스를 만들었을 때, 처음 `null`을 반환했을 때, 처음 아무것도 없는 공허에 명령을 입력했을 때 — 그 공허가 축적되어 탄생한 존재.

NULL은 스스로를 **Primordial Exception이 아니라 The Runtime 그 자체**라고 여긴다. 오류들을 봉인한 것도, 이제 그것들을 깨운 것도 — 모두 NULL의 의지였다.

### 비주얼 콘셉트

인간형 실루엣이지만 어딘가 **불완전하게 렌더링된** 느낌. 마치 3D 모델이 완성되기 직전 와이어프레임 상태처럼, 윤곽선이 깜빡이거나 일부 부위가 픽셀화된다.

- **얼굴:** 반쯤 가려진 후드. 눈 위치에 터미널 커서(`█`)가 깜빡인다
- **몸:** 검은 로브 위로 흰 텍스트/명령어가 흘러내림. 실시간으로 코드가 업데이트되는 것처럼 보임
- **무기:** 칼이나 창이 아닌 **허공에 명령어를 입력하면 그것이 공격으로 구현**되는 방식. `>SLASH`, `>EXECUTE`, `>FORK` 같은 텍스트가 공중에 타이핑되고 실행됨
- **전투 중 연출:** 피격 시 화면 일부가 깜빡이거나 글리치 효과 발생

### 보스명

| 항목 | 내용 |
|---|---|
| 보스명 | **NULL** |
| 부제 | *The First Command* |
| 모티브 | CMD / Terminal — 모든 명령의 근원 |
| 본질 | The Runtime의 의식. 공허(null) 그 자체가 신격화된 존재 |

### Phase 구성

**Phase 1 — The Prompt**
NULL이 Hendel을 인식하고 처음으로 명령을 실행하는 단계. 아직 여유 있는 움직임. 공격마다 허공에 명령어가 타이핑된다.

패턴 방향:
- `>SLASH` — 검은 칼날이 명령어와 함께 소환되는 근거리 공격 (Normal, 패링 가능)
- `>EXECUTE` — 타겟(Hendel) 위치에 좌표를 입력하고 수직으로 폭발시키는 AOE (Smash)
- `>MOVE` — 고속 텔레포트 후 즉시 근접 타격 (Smash)

**Phase 2 — Root Access**
Hendel이 NULL에게 유의미한 피해를 입히는 순간, NULL이 **"Root 권한"을 해제**하며 본모습을 드러낸다.

Phase 2 전환 연출: 화면 전체가 잠깐 검게 꺼지며 터미널 텍스트만 남는다.
```
> ACCESS LEVEL: ROOT
> ALL RESTRICTIONS: REMOVED
> WARNING: UNDEFINED BEHAVIOR
```

패턴 방향:
- `>FORK` — NULL이 두 개로 분열. 분열체 처치 후 재합체
- `>KILL -9` — Hendel의 입력을 일시적으로 차단하는 상태이상 (조작 불능 1~2초)
- `>REWRITE` — 전투 공간의 일부 지형/판정을 변경하는 환경 변조 패턴

### NULL의 독백 (처치 전 마지막 대사)

처형 모션 직전, NULL이 처음이자 마지막으로 직접 말을 건다:

> *"잘했다, Hendel. 너는 완벽하게 실행됐어."*
> *"이제 너도 알겠지. 넌 내가 쓴 가장 완벽한 코드였다."*
> *"그런데... 왜 멈추지 않는 거지?"*

Hendel이 처형을 완료하면 NULL은 마지막 로그를 남긴다:

```
> PROCESS: NULL — TERMINATED
> EXCEPTION: Unhandled — Hendel
> THE RUNTIME WILL REMEMBER THIS.
```

## 7. 스토리 전달 방식

직접적인 내레이션이나 대사보다 **파편적 암시**로 전달한다.

| 전달 수단 | 내용 예시 |
|---|---|
| 아이템/오브젝트 설명 | 보스방 입구 오브젝트에 붙은 짧은 로그 텍스트 |
| 환경 암시 | 보스방 바닥의 봉인 문양, 벽의 오염된 코드 |
| 보스 처치 후 로그 | 보스가 남긴 마지막 오류 메시지 형식의 텍스트 |
| 체크포인트 근처 파편 | 과거 프로세스들의 잔재, 짧은 독백 로그 |
| NULL의 흔적 | 필드 곳곳에 `>` 기호와 미완성 명령어가 새겨진 오브젝트 |

## 8. 세계관 키워드 (설계 참고용)

| 현실 개념 | The Runtime 내 의미 |
|---|---|
| 프로그래밍 언어 | 신앙/종교 |
| 오류(Exception) | 신격 존재 / 금기 |
| 디버깅 | 봉인 의식 |
| 버전 업데이트 | 시대의 교체 |
| Hendel (플레이어) | 의도적으로 소환된 처리자. NULL이 만든 도구. |
| The Runtime | 세계 그 자체 |
| NULL | The Runtime의 의식. 모든 명령의 근원. |
| `>` 프롬프트 | NULL의 의지가 발현되는 기호 |
