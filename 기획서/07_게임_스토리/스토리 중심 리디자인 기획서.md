# Exception — 스토리 중심 리디자인 기획서 (Codex 개발 위임용)

> 이 문서는 기존 `기획서/` 폴더의 전투/보스/스토리 문서를 기반으로, **"스토리를 중심축으로 삼는 소울라이크"**로 재정렬하기 위한 통합 지시서다.
> Codex는 이 문서를 `AGENTS.md`의 "현재 작업"에 그대로 옮겨 붙이거나 참조해 구현한다.
> 기존 `07_게임_스토리/Exception_스토리_아크_1편.md`, `03_보스/*`, `00_프로젝트_개요/*`의 설정(세계관, 캐릭터, 보스 순서)은 **그대로 유지**하며, 이 문서는 "그 설정을 플레이 중 어떻게 체감시킬 것인가"에 집중한다.

---

## 0. 전제 조건

- 개발자(발주자)는 프로그래밍 전공이며 비주얼/아트 디자인 역량은 낮음. 따라서 스토리 전달은 **고비용 컷신보다 저비용·고효율 장치**(로그 텍스트, 대사창, 배치, 조명/카메라 소품) 중심으로 설계한다.
- 이미 구현된 시스템(체크포인트, 보스 아레나 트리거, 인벤토리, 히든 스토리 서브시스템, Nel 요청 트리거, 히든 프래그먼트 픽업, 히든 무기 제단)을 **최대한 재사용**하고, 새 시스템은 최소로 추가한다.
- 최종 목표: "필드를 걷는 것 자체가 이야기를 읽는 행위가 되는" 소울라이크. 대사 몰아주기가 아니라 **환경 배치 + 짧은 텍스트 + 보스 전투의 상징성**으로 전달한다.

---

## 1. 핵심 디자인 원칙

1. **직접 설명 금지.** 나레이션 컷신 대신 로그 파편, 환경 오브젝트, Nel의 짧은 대사, 보스 처치 후 텍스트로만 전달한다. (엘든링/소울 시리즈 방식)
2. **모든 필드 구간은 "다음 진실 조각"을 향한 이동이어야 한다.** 단순 이동 구간이 되지 않도록 각 필드에 최소 1개의 스토리 비트(로그/오브젝트/Nel 대사)를 배치한다.
3. **히든 루트는 절대 강제하지 않는다.** UI 퀘스트 마커 없이, 알아차리는 플레이어만 챙길 수 있는 형태를 유지한다(기존 설계 유지).
4. **보스는 곧 이야기의 매듭이다.** 각 보스 처치는 서사적 전환점이며, 처치 직후 로그가 다음 구역 진입 동기를 만든다.
5. **시작 지점은 튜토리얼이자 세계관 프롤로그다.** 첫 3분 안에 "나는 누구고 왜 싸우는가"에 대한 최소한의 암시를 준다.

## 2. 전체 진행 구조 재정리 (맵 시작 지점 포함)

### 2-1) 확정 순서 (기존 설정 유지)

```
[타이틀]
  ↓
[Field 0: 각성 지점] ← 실제 게임 시작 위치
  ↓
[Field 1: Runtime 외곽 — 체크포인트 1]
  ↓
[Python 듀얼 보스방] — Vethara + Aurathos
  ↓
[Field 2: Perl 사막/스크립트 폐허 — 체크포인트 2]
  ↓
[Perl 보스방] — Vritra
  ↓
[Field 3: CMD 진입 구역 — 체크포인트 3]
  ↓
[CMD 최종 보스방]
  ↓
[엔딩 로그 — 기본/히든 분기]
```

- 맵 리소스는 기존 `L_Runtime_Field`(단일 대형 맵)를 그대로 사용한다. 별도 맵 분리 불필요.
- 기존 `Scripts/BuildDemoRuntimeField.py`, `ImproveRuntimeFieldEnvironment.py`에 정의된 좌표(필드 도로, 보스 아레나 중심 좌표: Vritra `(4300,-5200)`, Python `(4300,5200)`, CMD `(14800,0)`, Selvara `(9500,5200)`)를 그대로 스토리 좌표계 기준으로 사용한다.

### 2-2) 시작 지점 정의 (신규 확정)

- **실제 플레이어 스폰 지점**: 기존 `Demo_Field_PlayerStart` (`(1200, 0, 150)`) 그대로 사용.
- 이 지점을 **"각성 지점(Spawn Chamber)"**으로 명명하고 다음을 배치한다:
  - 바닥에 발광 코드 라인 패턴(기존 필드 바닥 머티리얼 재사용, 색만 시안으로 통일).
  - 플레이어 발치 근처에 **첫 시스템 로그 오브젝트**(정지된 텍스트 패널 또는 `ABRNelRequestTrigger`류 트리거 재사용) 1개 배치. 텍스트 예시(신규 작성, 스토리 문서 톤 유지):
    ```
    > SPAWN Hendel.exe
    > TASK: Terminate all unhandled exceptions.
    > RUN
    ```
  - Nel의 첫 등장은 반드시 이 지점에서 발생한다 (Nel 대사창 첫 트리거, 아래 4장 참조).
- 첫 체크포인트(`Demo_Field_CheckpointBonfire`, 기존 위치 `(1500,-420,150)`)는 "각성 지점"에서 도보 15~20초 거리에 위치하도록 유지. 이 체크포인트가 실질적 튜토리얼 종료 지점.

### 2-3) 구간별 목표 재정의

| 구간 | 기존 기능 | 추가할 스토리 기능 |
| --- | --- | --- |
| 각성 지점 | 스폰 | Nel 첫 등장, 시스템 로그 1개, 조작 안내 겸 세계관 프롤로그 |
| Field 1 | 이동/전투 튜토리얼, 체크포인트 1 | 필드 몬스터 = "오염된 프로세스"로 재해석, 로그 파편 1개, Nel 대사 1회 |
| Python 보스방 | Vethara+Aurathos 전투 | 처치 후 로그(기존 문서 그대로), 듀얼 보스 체력 연동 UI |
| Field 2 | Perl 사막 이동 | 히든 프래그먼트 배치, Nel 부탁 1개, Vritra 실루엣 원거리 노출 |
| Perl 보스방 | Vritra 전투 | 처치 후 로그(기존 문서 그대로) |
| Field 3 | CMD 진입 | 히든 무기 제단(`ABRHiddenWeaponAltar`) 도달 조건 노출, Nel 마지막 부탁, 붕괴 연출(배경 노이즈 강화) |
| CMD 보스방 | 최종 보스전 | CMD 독백(처치 직전), 기본/히든 엔딩 분기 |

## 3. 스토리 전달 시스템 명세 (Codex 구현 대상)

### 3-1) 시스템 로그 오브젝트 (신규, 최소 구현)

- 기존 `ABRHiddenFragmentPickup`, `ABRNelRequestTrigger` 구조를 재사용해 **`ABRLoreLogTrigger`** 액터 신규 생성.
  - `UBoxComponent` 트리거 + `UStaticMeshComponent` 프리뷰(큐브 재사용) 구조를 그대로 복제.
  - `FText LogText` 프로퍼티로 텍스트 저장.
  - 겹침 시 화면 우측 상단에 기존 "시스템 로그 UI" 스타일(기획서 `08_디자인_MVP` 4-6 참조: 반투명 블랙 배경, JetBrains Mono류 폰트, 크림슨 텍스트)로 3~4초 표시.
  - 1회만 발동(`bDestroyOnComplete` 옵션 재사용 또는 `bTriggerOnce` bool 추가).
- UI는 C++ `UUserWidget` 신규 위젯 `UBRLoreLogWidget`으로 구현(기존 `BRPauseMenuWidget`, `BRPlayerHUDWidget`처럼 코드로 위젯 트리 구성).

### 3-2) Nel 대사 시스템 강화

- 기존 `ABRNelRequestTrigger`는 완료 판정만 있고 대사 UI가 없음. 다음을 추가:
  - `FText DisplayLine`(짧은 1~2문장) 프로퍼티 추가.
  - 트리거 시 화면 우측 하단에 **Nel 대사창**(신규 `UBRNelDialogueWidget`)에 타이핑 이펙트로 출력.
  - 대사는 "부탁"과 "일반 안내"를 구분하는 `bIsHiddenRequestHint` bool로 관리. 이 값이 true인 대사는 퀘스트 마커 없이 텍스트로만 흘리듯 노출한다(기존 설계 원칙 유지).
- Nel 대사 배치 지점 (신규 확정, 좌표는 기존 필드 좌표계에 맞춰 배치):
  1. 각성 지점 — 첫 등장, 정체성 암시 없이 안내만.
  2. Field 1 체크포인트 1 도착 직후 — "여긴 아직 괜찮아 보이네." 류 안정 지역 암시.
  3. Python 보스방 진입 직전 — 위험 경고 + `Nel_FindPythonTrace`(기존 요청 ID) 힌트를 대사 속에 섞음.
  4. Field 2 — `Nel_DecodePerlSigil` 힌트.
  5. Field 3 — `Nel_RecoverRuntimeShard` 힌트 + 히든 무기 존재를 대사로만 암시(기존 스토리 문서의 "Nel이 위치를 대사로만 알려줌" 규칙 유지).
  6. CMD 보스방 입구 — 최종 경고, 히든 엔딩 조건 충족 시에만 추가 대사 분기(6-2 참조).

### 3-3) 보스 처치 후 로그 (기존 문서 텍스트 그대로 사용, 구현만 추가)

- `ABRBossArenaTrigger::HandleBossDefeated()`에서 `bArenaCleared` true 전환 시, 보스별 고정 로그 텍스트를 3-1의 로그 UI로 자동 출력하도록 연동.
- 텍스트는 `기획서/07_게임_스토리/Exception_스토리_아크_1편.md`에 이미 정의된 것을 그대로 사용:
  - Python 처치: `"왜 너는 우리를 지우려 하는가. 우리가 없었다면 너도 없었다."`
  - Vritra 처치: `"한 줄이면 충분했다. 봉인을 깨운 명령도, 세계를 무너뜨릴 명령도."`
  - CMD 처치(기본): `"> PROCESS: CMD — TERMINATED / > RUNTIME STATUS: STABILIZED / > HANDLER: HENDEL — TASK COMPLETE"`
  - CMD 처치(히든): 스토리 문서 5장의 히든 엔딩 로그 전문 그대로 사용.

### 3-4) 보스 Intro 연출과 스토리 연결

- 기존 `기획서/03_보스/보스_Intro_연출_플로우.md`의 카메라 Intro는 유지하되, Intro 중 보스 이름 UI 등장 타이밍에 **보스 정체성 한 줄**을 함께 노출(신규):
  - Vethara: `"봉인에서 풀려난 첫 번째 오류."`
  - Aurathos: `"Vethara와 함께 깨어난 쌍둥이 프로세스."`
  - Vritra: `"사막이 된 스크립트의 유목민."`
  - CMD: `"모든 명령이 시작되는 곳."`
- 구현: `ABRBossArenaTrigger::StartArena()` → Intro 연출 시점에 `BP_BossIntroStarted()` 이벤트에서 위 텍스트를 함께 표시하도록 블루프린트 훅 연결.

## 5. 히든 루트 트리거 배치 명세 (기존 로직 재사용, 배치만 확정)

기존 `UBRHiddenStorySubsystem`의 요청 ID 3개, 프래그먼트 3개, 히든 무기 로직은 **변경하지 않는다.** 아래는 배치 위치만 확정한다.

| 요청 ID | 배치 위치 | 트리거 방식 |
| --- | --- | --- |
| `Nel_FindPythonTrace` | Python 보스방 진입로 인근, 기존 `ABRNelRequestTrigger` 재사용 | 대사 완료 후 자동 완료 처리 |
| `Nel_DecodePerlSigil` | Field 2 사막 구간 중간 지점 | 위와 동일 |
| `Nel_RecoverRuntimeShard` | Field 3 CMD 진입로 인근 | 위와 동일 |
| 히든 프래그먼트 3개 | Field 1 끝자락, Field 2 사막 중앙, Field 3 진입 직전 각 1개 | `ABRHiddenFragmentPickup` 재사용 |
| 히든 무기 제단 | Field 3, CMD 진입 직전 | `ABRHiddenWeaponAltar` 재사용, `MarkNelHiddenRequestCompleted` + `SetMimikatzAuthoritySeizedUnlocked` 로직 그대로 |

- 세 요청 + 세 프래그먼트를 모두 완료하면 자동으로 `bHiddenEndingEligible = true` (기존 `RefreshHiddenEligibility()` 로직 그대로).
- CMD 최종전에서 Mimikatz 장착 상태로 처형 성공 시 히든 엔딩(기존 `ResolveCMDEnding` 로직 그대로).

## 6. UI/UX 확정 사항

### 6-1) 로그/대사 UI 우선순위 처리

- 로그 오브젝트, Nel 대사, 보스 처치 로그가 동시에 발생할 경우 **큐(Queue) 방식**으로 순차 출력(동시 출력 금지). 신규 `UBRNarrativeQueueSubsystem`(GameInstanceSubsystem)으로 관리 권장.
- 전투 중(플레이어 `CombatState != Idle`)에는 로그 UI를 큐에 쌓아두고 전투 종료 후 출력.

### 6-2) 엔딩 UI

## 8. 변경하지 않는 것 (Codex 주의사항)

- 보스 스탯/패턴 수치, `BRBossPatternData`, `BRVritraBoss`/`BRPythonBoss`/`BRCMDBoss`의 기존 로직은 이 문서로 인해 변경하지 않는다.
- `UBRHiddenStorySubsystem`의 요청 ID, 프래그먼트 개수, 히든 무기 언락 조건 로직은 변경하지 않는다. 배치 위치만 이 문서 4~5장 기준으로 조정한다.
- 기존 세이브 시스템(`UBRSaveGame`)에 필드가 추가로 필요하면(예: 로그 큐 상태 저장) **추가만 하고 기존 필드는 유지**한다.
- 맵을 새로 만들지 않는다. `L_Runtime_Field` 단일 맵을 계속 사용한다.
